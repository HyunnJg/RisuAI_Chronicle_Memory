# Chronicle Memory v0.7.8

새 구간만 압축해 시간순 사건 로그에 덧붙이는 RisuAI API 3.0 플러그인입니다. 단독과 하이브리드 모두 **누적 요약 로그 전체 + 선택한 방식으로 유지한 원문 + 현재 입력**을 보냅니다. 자체 하이브리드는 관련 요약 청크를 검색해 현재 입력 가까이에 다시 제시합니다. 새 **Risu 기억 병행 · 하이파 주력**은 원문·과거 검색을 Risu에 맡기고 짧은 연대기를 덧붙입니다.

## v0.7.8 추가 요약 지침 프리셋

요약 연결 영역의 **추가 요약 지침**을 이름별로 저장하고 불러올 수 있습니다. 기존 지침은 그대로 남으며 기본 제공 지침이나 모드 자동 전환을 강제하지 않습니다.

1. 위 편집칸에 원하는 지침을 적습니다.
2. **지침 프리셋 저장·관리**를 펼쳐 ‘단독용’, ‘하이파 병행용’처럼 이름을 붙이고 **새 프리셋 저장**을 누릅니다. 같은 이름으로 새 저장하면 기존 내용을 덮어쓰지 않고 안내합니다.
3. 다른 지침도 별도 이름으로 저장합니다. 빈 지침도 ‘추가 지침 없음’ 등의 이름으로 보관할 수 있습니다.
4. 다시 쓸 때 목록에서 골라 **선택 지침 불러오기**를 누릅니다. 위 편집칸이 선택한 내용으로 교체됩니다. 아직 저장하지 않은 편집 내용이 있다면 먼저 별도 프리셋으로 보관하세요.
5. 내용을 확인하고 **전체 설정 저장**을 눌러 적용합니다. 새로 요약하는 구간부터 사용하고 기존 청크는 다시 요약하지 않습니다.

**선택 프리셋 수정**은 현재 선택한 항목을 위 편집칸과 이름으로 수정합니다. 이름 변경도 가능합니다. **선택 프리셋 삭제**는 대상을 표시한 뒤 삭제 확인·취소를 제공합니다. 프리셋을 삭제해도 현재 편집칸과 이미 적용한 지침은 유지합니다. 다른 화면에서 바뀐 저장본을 발견하면 오래된 선택으로 덮어쓰지 않고 다시 열도록 안내합니다. 여러 탭의 동시 저장을 원자적으로 잠그는 기능은 아닙니다.

프리셋 저장·수정은 지침 보관함만 저장합니다. API 키·모델·다른 설정을 함께 저장하거나 호출하지 않습니다. 실제 적용은 기존 전체 설정 저장을 사용합니다. 모드를 바꿀 때 지침이 자동 전환되지 않으므로 필요하면 원하는 프리셋을 직접 불러오세요. 모듈에서 모드를 바꿔도 지침은 플러그인 공통 설정을 따릅니다.

프리셋은 같은 Risu 저장 환경에서 채팅 간에 공유하고 다시 열어도 남습니다. 기기·저장본 간 자동 동기화는 호스트의 저장 방식에 따릅니다. 채팅 기억·검색 캐시 삭제와 별도로 관리하며 **기억 JSON 백업에는 프리셋이 들어 있지 않습니다**. 중요한 지침은 별도로 복사해 보관하세요. 프리셋 데이터가 손상되더라도 원래 적용 지침과 RP 요청은 계속 사용하고 손상된 보관함을 자동 초기화하지 않습니다.

## v0.7.7 원문 자르기 방식 선택

단독·자체 하이브리드에서 **매 턴 이동(기본)** 또는 **청크 커밋 시 이동(계단식)**을 선택합니다. Risu 기억 병행에서는 하이파 등 Risu가 원문을 관리하므로 이 옵션은 적용하지 않습니다.

- 매 턴 이동: 현재 완료 턴 수에서 최근 N턴을 기준으로 원문 시작점을 매번 이동합니다. 미요약 구간은 추가로 유지합니다. 구버전과 같은 기본 동작입니다.
- 계단식: 마지막으로 저장한 요약 청크의 끝에서 최근 N턴을 남깁니다. 다음 청크가 저장될 때까지 시작점을 고정하고 새 원문을 덧붙입니다. 청크 저장 시 시작점이 한 번에 이동합니다.
- 주기 5·최근 원문 5이고 요약이 정상적으로 따라가는 경우, 완료 10~14턴에서 원문 T6~T10 → T6~T14를 유지합니다. 15턴 청크가 저장되면 원문 T11~T15로 이동합니다. 완료 원문이 5~9턴, 같은 길이의 턴이라면 평균 약 7턴입니다.
- 실패·중단·초기 따라잡기 중에는 더 많은 원문이 남습니다. 커밋하지 못한 요약으로 경계를 앞당기지 않습니다. 원문 수정·삭제·분기·백업 복원·설정 변경 시에는 유효한 요약과 현재 설정으로 범위를 다시 계산합니다.
- 요약 주기와 최근 원문 수는 독립적입니다. 기존 청크를 다시 요약하거나 별도의 경계 상태를 저장하지 않습니다. 자체 검색도 같은 원문 경계를 기준으로 하며 아직 원문에 완전히 남은 청크는 재강조하지 않습니다.

플러그인 기본값의 **원문 자르기 방식**에서 선택합니다. 새 Control 모듈 v0.7.7에서는 **플러그인 기본값 / 매 턴 이동 / 청크 커밋 시 이동**을 고를 수 있습니다. 모듈의 기억 사용을 ‘모듈설정 사용’으로 해야 해당 선택이 적용됩니다. 이전 모듈은 새 변수를 설정하지 않는 경우 플러그인 기본값을 따르지만, 모듈에서 선택하려면 함께 교체하세요.

같은 청크 사이에서 누적 로그와 원문 앞부분이 유지돼 캐시 활용에 유리할 수 있지만 입력 원문은 더 길어집니다. 모델·캐시 만료·캐시 지점·동적 상태창·프롬프트 순서·자체 검색 결과에 따라 실제 적중과 비용이 달라집니다. 실제 API 캐시 적중률·절감액은 이번에 측정하지 않았습니다. Risu가 이미 제외한 원문은 복원하지 못합니다.

## v0.7.6 연결·복원 보안 보강

- 직접 입력 요약·별도 임베딩 키를 서버 origin(프로토콜·호스트·포트)에 연결해 저장합니다. 주소가 달라지면 키 전송을 차단합니다. 같은 origin 안의 경로 변경은 허용합니다.
- 이전 버전의 직접 입력 키는 주소 정보가 없어 자동 사용하지 않습니다. 설정창에서 현재 주소를 확인한 뒤 ‘현재 주소에 이 키 연결’ → 전체 설정 저장을 한 번 수행하세요. 새로 입력하는 키는 입력 시점의 유효한 주소에 연결됩니다. 익명 연결과 고정 제공자의 기존 키는 유지합니다.
- Vertex 서비스 계정 JSON은 기본 화면에서 가리고 계정 이메일만 표시합니다. 명시적 표시·교체를 제공하며 빈 편집칸으로 기존 키를 지우지 않습니다. 삭제는 인증정보 삭제 체크를 사용합니다.
- 예약된 기억·검색 마커를 주입 출력에서만 치환합니다. 저장 원문·요약과 원문 변경 감지 해시는 유지합니다. 이는 프롬프트 인젝션 전체를 차단하는 보안 경계가 아닙니다.
- 백업 복원의 보관함을 평탄하게 합치고 동일한 전체 기록 버전만 중복 제거합니다. 같은 ID라도 내용이 다른 수정본은 남깁니다. 같은 상태 복원은 기록·보관함·revision을 늘리지 않습니다. 보관함 개수·용량의 임의 상한은 추가하지 않았습니다.
- Voyage·Groq·xAI 패턴과 현재 작업에서 읽은 실제 키의 오류 마스킹을 보강했습니다. 채팅 설정 덮어쓰기 표시, localhost 통신 오류 안내와 Actions 커밋 SHA 고정을 추가했습니다.

### 저장소와 백업의 신뢰 범위

safeLocalStorage는 기기 로컬 저장소이며 플러그인별 비밀 금고가 아닙니다. 확인한 Risu 본체 구현에서 다른 설치 플러그인이 같은 저장 API로 키·사건 로그를 읽거나 쓸 수 있습니다. 이 플러그인의 키 접두사와 origin 연결은 다른 악성 플러그인으로부터 격리를 제공하지 않습니다. 신뢰하는 플러그인만 설치하고 외부 키는 전용 키·최소 권한 계정을 권장합니다. Risu 내부 모델 경로는 연대기에 별도 키 사본을 저장하지 않지만 악성 플러그인에 대한 완전한 방어를 의미하지 않습니다. PocketRisu 등 다른 호스트의 격리·동기화 동작은 해당 구현을 별도로 확인해야 합니다.

백업의 해시는 현재 원문 구간과의 일치를 확인합니다. 요약 본문의 작성자·진실성·변조 방지를 인증하는 서명이 아닙니다. 신뢰하는 백업만 복원하세요. API 요청·키는 Risu 설정에 따라 선택된 프록시를 경유할 수 있습니다.

## v0.7.5 대기 중단·전체 원문 검증 최적화

- 요약 대기 중에도 설정창을 열어 상태·기록을 읽을 수 있습니다. 저장·수정·삭제는 기존처럼 순서대로 처리합니다.
- ‘이번 기억 호출 기다리기 중단’을 누르면 해당 응답을 더 기다리지 않고 저장한 청크와 미요약 원문으로 진행합니다. 요약·임베딩·연결 시험·모델 목록에 적용하며 강제 대기 제한은 없습니다.
- 늦은 응답은 기록·벡터·화면 결과에 반영하지 않습니다. 이미 시작한 서버 호출과 과금 취소는 보장하지 않습니다. 중단한 호출의 후속 API 호출은 생략하고, 그 호출이 끝날 때까지 같은 채팅에서 새 기억 호출을 시작하지 않습니다. 끝난 뒤에는 기존 재시도 대기 또는 수동 요약을 사용합니다. 대기 상태가 끝나지 않으면 Risu 재시작으로 이 실행의 대기 상태를 초기화할 수 있으나 서버 호출 취소를 뜻하지는 않습니다.
- 본문·화자·역할·메시지 ID 전체가 같은 연속 앞부분에만 SHA-256 결과를 재사용합니다. 과거 수정·삭제·분기 감지를 유지하며 재검증은 최신 원문 전체를 비교합니다. 캐시는 메모리의 직전 스냅샷 하나이며 저장 형식을 바꾸지 않습니다.
- 삭제는 브라우저 confirm 대신 대상·삭제 확인·취소를 표시합니다. 확인창을 연 뒤 채팅을 옮겨도 표시한 대상만 삭제합니다.
- Risu 프록시 경유 가능성과 지연 저장 안내를 추가했습니다. npm test는 먼저 필요한 설치 파일을 빌드합니다.
- 최근 원문 창·요약 주기·제공자 요청 옵션은 유지합니다. 계단식 원문 유지, 일반 HTTP용 암호 대체 구현은 추가하지 않았습니다.

## v0.7.3 웹·모바일 안전장치

- 설정창 상단에 환경 진단과 최근 기억 처리 결과를 표시하고 작은 별도 상태로 저장합니다. Web Crypto 미지원 시 원문을 자르지 않고 RP를 통과시키며 HTTPS·최신 브라우저 안내를 남깁니다.
- JSON 백업은 먼저 준비한 뒤 사용자가 저장 링크를 직접 누릅니다. 임시 URL을 1초 뒤 자동 폐기하지 않으며 새 백업·설정창 닫기에서 해제합니다. 다운로드 미지원 시 JSON 전체 선택·복사를 제공합니다. 파일 읽기는 File.text와 FileReader를 지원합니다.
- 요약 중 상태를 남기고 응답 대기 중 중복 재시도하지 않습니다. 저장 완료 청크는 유지하고 재시작 시 남은 구간부터 확인합니다. 화면 잠금 중 실행 지속과 기기·탭 간 동시 호출 조정은 보장하지 않습니다.
- 좁은 화면에서는 설정을 한 열로 배치하고 입력 글자·버튼 터치 영역을 늘렸습니다. 원문 전체 해시 검증·요약 정책·캐시 키는 유지합니다.
- 실제 Risu 웹·PocketRisu·Android·iOS 검증은 하지 않았습니다. 자동 테스트·DOM 모의 검증 결과는 검증 문서에서 구분합니다.

## v0.7.1 기능 변경

- **요약 최종 JSON과 함께 반환된 추론 표시를 분리합니다.** Risu의 선행 `<Thoughts>`·`<think>` 등 닫힌 블록을 제외하고 정상 최종 JSON을 읽습니다. 일반 설명이 앞뒤에 붙어도 완성된 요약 객체가 하나일 때만 수용합니다. 본문 안의 태그·따옴표·중괄호는 보존합니다.
- 여러 요약 객체·닫히지 않은 추론 블록·잘린 JSON·틀린 턴 범위는 추정 복구하지 않고 실패로 처리합니다. Risu 스트림의 별도 thought/reasoning 필드는 최종 답변과 합치지 않습니다.

### v0.7.0에서 유지되는 변경

## 설치·업데이트

1. 중요한 기록은 기존 버전에서 JSON 백업을 받아둡니다.
2. `Chronicle_Memory_v0.7.7.js`로 플러그인을 업데이트하고 이전 플러그인을 동시에 켜지 않습니다.
3. 이전 Control 모듈을 끄고 **모듈 관리**에서 `Chronicle_Control_v0.7.7.charx`를 가져와 활성화합니다. `.risum`은 같은 기능의 대안이며 둘 중 하나만 설치합니다. `.module.json`은 소스 확인용입니다.
4. 단독·자체 하이브리드는 Risu 내장 기억을 끕니다. **Risu 기억 병행은 하이파 등 내장 기억을 Risu에서 직접 켭니다.** 플러그인은 내장 기억 설정을 대신 변경하지 않습니다.
5. 플러그인 설정 → Chronicle Memory에서 요약 모델을 연결합니다. 하이브리드는 임베딩 모델도 연결합니다.
6. Risu 기본 토글 영역 → 📜 Chronicle Memory → **기억 사용: 모듈설정 사용**을 선택합니다.

플러그인 식별자 `RisuChronicleMemory`, 저장소 이름, 백업 형식은 유지했습니다. 기존 키·로그·수동 편집을 이어서 읽습니다. 기존 채팅을 사용할 때 기록에 들어 있던 활성 벡터는 별도 캐시로 옮기고 보관함의 벡터는 제거합니다. 로그 본문은 다시 요약하지 않습니다. 기존 백업의 벡터는 읽을 수 있지만 새 백업에는 재생성 가능한 벡터를 넣지 않습니다.

이전 모듈도 핵심 제어는 전달하지만 삭제된 상한·대기 제한 입력이 보이므로 새 모듈로 교체하세요. 이전 ‘추가 주입/하이파 병행’ 값은 새 하이브리드로 읽고 안내합니다.

모드만 바꿔도 기억이 자동으로 켜지지는 않습니다. 모듈 변경은 **다음 요청 시작 시** 반영됩니다. 대화별로 다르게 쓰려면 Risu의 **로컬 토글**을 켜세요. 모듈을 끄기 전에 플러그인 기본값으로 한 번 반영하면 기존 채팅 변수도 상속 상태로 돌아갑니다.

| 구성 | 단독 | 자체 하이브리드 | Risu 기억 병행 |
|---|---|---|---|
| 새 구간 요약·전체 기록 저장 | 사용 | 사용 | 사용 |
| 연대기 주입 | 전체 | 전체 | 전체 기본, 최근 K / 기록만 선택 |
| 원문 관리 | 연대기 최근 N턴 | 동일 | Risu 내장 기억 |
| 자동 과거 검색 | 없음 | 연대기 청크 검색 | Risu 내장 기억 |
| 턴당 본문 권장 목표 | 일반 설정 100글자 기본 | 동일 | 별도 50글자 기본 |


단독·자체 하이브리드 예: 완료된 12턴 중 T1~T10을 요약했고 최근 원문이 5턴이면 **로그 T1~T10 + 원문 T8~T12 + 현재 입력**을 보냅니다. 하이브리드는 관련 요약 청크를 현재 입력 가까이에 추가합니다. 전체 로그의 시간순서는 유지하고 오래된 원문은 검색·재주입하지 않습니다.

1턴은 완료된 AI 응답 1개입니다. 사용자 입력 없이 **별도 메시지로 진행한 AI 응답도 각각 1턴**으로 셉니다. 첫 인사·미응답 입력은 세지 않으며, 연속 사용자 입력은 다음 응답과 한 턴으로 묶습니다. 기존 메시지에 내용을 붙이는 이어쓰기·기존 응답의 재생성은 턴 수를 늘리지 않습니다. 주기를 채우면 다음 RP 요청 직전에 요약합니다. 단독·자체 하이브리드에서 **미요약·실패 구간과 현재 입력은 최근 N턴을 초과해도 유지**합니다. Risu 병행은 내장 기억이 남긴 원문을 그대로 사용하므로 이미 제외된 미요약 원문을 복원하지 않습니다. 실제 저장 대화를 삭제하지 않습니다. 10번째 응답이 완료되면 6~10턴 요약은 11번째 RP 요청 직전 또는 설정 화면의 ‘미처리 구간 요약’에서 실행합니다.

전체 원문을 확인해 수정·삭제·재생성·분기를 감지하며 바뀐 구간과 모든 후속 기록을 보관함으로 옮깁니다. 해당 기록은 검색·주입에서 제외합니다. 처리 중 원문·채팅이 바뀌면 결과를 폐기하고 요청을 중단해 오래된 기억이 섞이지 않게 합니다.

단독·자체 하이브리드에서 최근·미요약 원문의 ID를 요청에서 확인하지 못하면 추가로 자르지 않고 로그만 붙이며 경고를 남깁니다. Risu가 훅 전에 이미 제외한 원문은 복원하지 못합니다.

## 하이파 주력 병행 설정

1. Risu에서 하이파 등 사용할 내장 기억을 켜고 토큰 예산과 원문 보존 범위를 설정합니다.
2. 새 Control 모듈 → 기억 사용: 모듈설정 사용 → 원문 처리: Risu 기억 병행 (하이파 주력).
3. 요약 주기 5턴, 병행 전용 턴당 요약 목표 50글자, 병행 연대기 주입: 누적 로그 전체로 시작할 수 있습니다. 각각 가변 값이며 최적값을 보장하는 설정은 아닙니다.
4. 이 모드에서는 기존 ‘최근 원문 수’와 일반 ‘턴당 평균 요약 목표’가 적용되지 않습니다. 병행 전용 목표를 사용합니다. Risu의 원문 보존 단위와 Chronicle의 완료 턴 수는 다를 수 있습니다.
5. 선택한 주입 범위는 주입 미리보기·청크 수에 반영됩니다. 최근 K청크는 저장 순서의 마지막 K개를 뜻하며 저장·백업·편집에서 오래된 기록을 지우지 않습니다. 기록만도 요약 호출과 저장은 계속합니다.

하이파는 연대기가 원문을 자르기 전의 Risu 이력을 기준으로 작동합니다. 연대기 로그는 내장 기억 처리 뒤 추가되므로 하이파가 연대기 자체의 누적 크기를 줄여주는 것은 아닙니다. 전체 로그 주입을 선택했다면 그 크기를 위한 최종 컨텍스트 여유를 Risu에서 확보하세요. 병행은 Risu의 출력 한도·메모리 비율·모델을 자동 변경하지 않습니다.

기존 로그는 그대로 사용하며 이전 구간을 더 짧게 다시 생성하지 않습니다. 전환 후 새 구간부터 병행 전용 지침과 목표를 사용합니다. 다시 단독·자체 하이브리드로 돌아가면 일반 원문·목표 설정을 적용하고, 저장한 기록은 계속 유지합니다. 원문 수정·삭제·분기 검증도 유지합니다.

## 범용 요약과 시점 표현

```text
다음 만남과 호칭에 대한 약속 (1–5턴)
다음 날 저녁 — 서점 앞에서 다시 만나기로 함.
둘만 있을 때는 이름으로 부르기로 합의함.
```

기본 지침은 중요한 행동·선택·발언·약속·관계 변화·명시된 감정·취향·경계·미해결 과제를 간결하게 보존합니다. 수량·날짜·장소·소유권도 중요하면 남깁니다. 확정 사건과 예정·주장을 구별하고 근거 없는 심리를 창작하지 않습니다. 카드 제목만으로 플레이어나 모든 발화자를 단정하지 않습니다.

요약 언어는 추가 지침을 우선하고 없으면 대화의 주된 언어를 따릅니다. 작품별 인물·장부·상태 해석이나 기록 문체는 **추가 요약 지침**에 적으세요. 기본 JSON 키는 변경하지 않는 것이 좋습니다.

예: 역사 시뮬레이션에서는 병력·부채·계약 수량과 상태 필드의 의미를 지침으로 정할 수 있습니다. 관계 중심 대화에서는 호칭·신뢰·취향·경계를 우선하도록 지정할 수 있습니다. 별도 프리셋을 강제하지 않습니다.

날짜는 원문 표현을 보존합니다. YYYY.MM.DD, 세 자리 연도, ‘다음 날’, ‘제국력 3년 봄’, 부분 날짜를 허용합니다. 일반 달력으로 해석되는 날짜만 표기를 정리하고 해석할 수 없는 표현은 그대로 남깁니다. 날짜가 없으면 ‘시점 미상’을 반복하지 않고 본문만 표시합니다. 현실의 현재 날짜를 넣으라고 지시하지 않습니다.

**기록 내용 목표 = 요약 주기 × 턴당 평균 글자 수.** 5턴 × 100글자면 내용 약 500글자가 권장 목표입니다. 중요한 사실이나 추가 지침 때문에 길어져도 정상 요약은 그대로 저장합니다. 글자 수의 강제 상한은 없습니다. summary 내용과 그 사이 줄바꿈만 세며 날짜·시간 표시·제목·키워드는 제외합니다. 이 요소들은 모두 출력 토큰을 소비하므로 JSON이 잘리면 출력 상한을 늘리세요.

정확한 턴 범위·정상 JSON·비어 있지 않은 본문은 검증합니다. 권장 분량 초과는 실패가 아니며 원문을 추가 유지하는 사유도 아닙니다. 별도로 저장된 실제 응답 토큰 상한은 제공자 경로에서 적용되며, 응답 잘림·JSON 오류·턴 범위 오류·빈 본문 등 실제 실패일 때는 원문을 남깁니다. 제목이 없으면 기본 제목, 키워드가 없으면 본문 검색을 사용합니다. 권장 길이를 넘긴 제목·이름·키워드를 임의로 자르지 않습니다. 정리한 항목은 경고로 확인할 수 있습니다. 형식 검증은 사실성 검증을 뜻하지는 않습니다.

재강조 길이는 관련 기록을 **추가로 반복해 보여주는 분량**이며 누적 로그 전체는 별도로 계속 보냅니다. 누적 로그 글자 상한·요약 대기 제한 항목은 없습니다. 전체 컨텍스트·출력·실제 비용은 Risu와 제공자 설정을 확인합니다. 플러그인은 응답을 기다리며 인위적인 시간 제한을 걸지 않지만 제공자·Risu 자체 제한은 별개입니다.

요약 제공자: Risu 메인·보조·기억 전용모델, OpenAI, Gemini AI Studio, Anthropic, Vertex AI, 직접 입력 OpenAI 호환 서버를 지원합니다. 주요 제공자는 주소를 자동 구성하고 모델 목록을 조회합니다. Risu 내부 호출은 프롬프트 토큰 목표를 전달하며 실제 출력 상한은 Risu 설정을 따릅니다. 외부 API는 출력 제한 필드를 보냅니다.

임베딩 제공자: Gemini AI Studio, OpenAI, **Voyage AI**, Vertex AI Google 임베딩, 직접 입력 OpenAI 호환 서버를 지원합니다. 요약 모델과 임베딩 모델은 다른 용도이며 별도로 지정합니다. Risu에 등록된 임베딩 직접 호출 경로는 현재 지원하지 않습니다.

Voyage는 전용 키와 voyage-4-large 기본 모델을 제공합니다. 내장 기본 모델 목록은 공식 문서 기준이며 실시간 권한 조회가 아닙니다. 기존 직접 입력의 정식 Voyage 주소도 전용 필드(output_dtype, input_type, truncation)로 처리합니다.

Vertex는 서비스 계정 JSON·프로젝트·리전을 사용합니다. 임베딩 모델에 맞춰 predict 또는 embedContent 형식을 선택하세요. 개인키로 고정 Google OAuth 서버에서 단기 토큰을 받고 개인키를 추론 API에 보내지 않습니다. 계정 권한·결제·리전별 사용 가능 여부는 연결 시험으로 확인합니다.

인증정보 재사용은 주요 제공자의 고정 API에서 같은 제공자의 저장 키를 사용합니다. **직접 입력은 요약 URL과 임베딩 URL의 origin이 같을 때만** 키를 재사용합니다. 요약 모델이 다른 제공자라면 저장된 external 프로필의 URL을 비교합니다. origin이 다르거나 확인할 수 없으면 키를 보내지 않으며 재사용 체크를 해제하고 임베딩 전용 키를 입력해야 합니다. 전용 키 선택 시에는 사용자가 지정한 임베딩 주소에 해당 키를 보냅니다.

전체 설정 저장 버튼·모델 목록 조회는 화면 전체 설정을 저장합니다. 목록에서 선택 후 다시 저장하세요. 연결·검색 시험은 사용자 실행 시 API 호출 비용이 발생할 수 있습니다.

## 검색과 저장

1. 제목·본문·키워드를 임베딩해 요약과 분리된 검색 캐시에 저장합니다. 새로운 청크·편집·모델 변경에 필요한 벡터만 만듭니다.
2. 현재 입력과 직전 2턴 일부로 검색 질의를 만들며 구조화된 상태 블록은 질의에서 제외합니다. 오래된 원문은 검색 대상에 넣지 않습니다.
3. 같은 모델·연결 설정의 벡터끼리 코사인 유사도를 계산합니다. 순위는 의미 80% + 키워드 일치 비율 20%입니다. 의미 최소값을 넘거나 키워드가 일치한 청크만 후보이며 기준 미달의 의미 점수는 가산하지 않습니다.
4. 최근 원문 안에 완전히 포함된 청크는 재강조에서 제외합니다. 경계를 걸쳐 오래된 사건도 담은 청크는 후보로 남깁니다. 정해진 개수·추가 길이 안에서 청크 전체를 다시 제시하며 재요약하거나 중간을 자르지 않습니다.
5. 임베딩 미설정·실패 시 키워드 검색으로 계속하고 안내합니다. 오류 후 60초 자동 재시도 간격을 두며 수동 저장·검색 시험으로 다시 시도할 수 있습니다.

검색은 모델 내부 어텐션 값을 직접 조절하지 않습니다. 요약에서 빠진 사실을 원문에서 복원하지도 않습니다. 과거 기록보다 이후 변경·최근 원문을 우선하도록 안내합니다. 실제 검색 품질은 대화로 확인해야 합니다.

요약 기록은 지속 보관합니다. 벡터는 별도의 검색 캐시이고 변경될 때만 저장합니다. 질의 벡터는 실행 중 메모리에만 두며 최근 검색 미리보기는 작은 별도 저장 항목입니다. 매턴 요약과 벡터 전체를 함께 직렬화하지 않습니다. 최근 몇 채팅의 벡터만 메모리에 유지하고 필요하면 저장 캐시에서 다시 읽습니다.

청크 편집·원문 분기로 달라진 벡터를 무효화하고 보관함에는 벡터를 넣지 않습니다. 활성 청크 벡터 초기화는 요약을 유지하며 다음 검색에서 재색인합니다. 채팅 이동·분기에서도 공통 원문이 일치하는 구간만 재사용하고 다른 이야기·캐릭터의 기억을 섞지 않습니다.

## 입력 정리·편집·백업·삭제

입력 정리는 알려진 이미지·BGM 매크로와 HTML 장식을 정리하며 이미지 설명 문구를 보존합니다. 구조화된 상태 JSON과 알 수 없는 사용자 태그는 원문 그대로 남깁니다. 특정 상태 이름·플레이어 필드를 해석하거나 상태 스냅샷을 차분으로 바꾸지 않습니다. 첨부 미디어 자체는 요약에 전송하지 않습니다. 원본 저장과 전체 원문 해시는 바꾸지 않습니다.

제목·키워드·본문을 편집한 뒤 ‘수정한 로그 저장’을 누릅니다. 자동 요약은 기존 수동 편집을 덮어쓰지 않습니다. 언어·감정·관계·작품별 규칙은 추가 지침에서 정합니다.

JSON 백업에는 활성 로그·수동 편집·보관함을 넣고 **벡터·질의 캐시·검색 결과·인증정보는 제외**합니다. 이전 벡터 포함 백업도 읽고 필요한 활성 벡터는 별도로 이관합니다. 일반 채팅 이동에는 JSON을 반복해 가져올 필요가 없습니다.

**삭제 위치: Risu 설정 → Chronicle Memory → 저장된 기억 · 캐시 관리.** 현재/선택/전체 기억 삭제는 해당 로그·보관함·별도 벡터·검색 캐시를 함께 지웁니다. 다른 분기에 복사된 기록까지 지우려면 전체 기억 삭제를 사용하세요. 전체 삭제는 부모 로그가 없는 파생 캐시도 함께 정리합니다. 원문·설정·API 키는 유지하며 계속 자동 요약하면 이후 새 기록이 만들어질 수 있습니다.

그룹 채팅 등 현재 편집 가능한 1:1 대화가 없어도 저장된 기억 목록을 보고 삭제할 수 있습니다. 지원하지 않는 대화의 요청은 변경하지 않습니다. 손상된 설정은 자동 덮어쓰지 않고 RP 요청을 통과시키며 설정 화면에 기본값을 표시합니다. 값을 검토하고 전체 설정 저장으로 복구하세요.
