# Chronicle Memory · 연대기 메모리

RisuAI 대화를 일정 턴 단위의 짧은 사건 기록으로 남기는 장기기억 플러그인입니다. 기존 기록을 반복해서 재요약하지 않고 새 구간을 시간순으로 쌓습니다. 캐릭터 RP와 일반 대화에 사용할 수 있으며 특정 작품의 지침을 강제하지 않습니다.

**v0.7.5 · 공개 베타 · RisuAI 플러그인 API 3.0 · GPL-3.0-only**

[설치 파일 다운로드](https://github.com/HyunnJg/RisuAI_Chronicle_Memory/releases) · [빠른 시작](QUICK_START_KO.md) · [전체 설정 안내](README_KO.md) · [검증 범위](VALIDATION_v0.7.5.md) · [변경 내역](CHANGELOG.md)

## 설치

1. Releases에서 `RisuAI_Chronicle_Memory_v0.7.5.zip`을 받아 압축을 풉니다. 소스만 필요한 경우 GitHub의 Source code도 사용할 수 있습니다.
2. Risu 설정의 플러그인 관리에서 `Chronicle_Memory_v0.7.5.js`를 가져옵니다. 이전 버전과 동시에 켜지 않습니다.
3. 모듈 관리에서 `Chronicle_Control_v0.7.5.charx`를 가져와 활성화합니다. `.risum`도 같은 모듈이므로 둘 중 하나만 설치합니다. `.module.json`은 소스 확인용입니다.
4. 플러그인 설정에서 요약 제공자·모델을 연결하고 기억을 켭니다. 모듈에서 값을 바꾸려면 **기억 사용 → 모듈설정 사용**을 선택합니다. 처음에는 기억이 꺼져 있습니다.
5. 중요한 기존 기록은 JSON으로 백업한 뒤 업데이트하세요. 기존 설정·키·저장 기록은 그대로 사용합니다.

## 모드 선택

| 모드 | 연대기 역할 | 원문 관리·과거 검색 |
|---|---|---|
| 단독 | 누적 사건 기록 전체 + 최근 N턴 원문 | 연대기가 원문을 관리, 별도 검색 없음 |
| 자체 하이브리드 | 단독 방식 + 관련 요약 청크 재강조 | 연대기가 원문과 임베딩·키워드 검색 관리 |
| Risu 기억 병행 | 짧은 연대기 기록을 보조로 주입 | 하이파 등 Risu 내장 기억이 담당 |

단독·자체 하이브리드는 Risu 내장 기억을 끄고 사용합니다. 병행 모드에서는 Risu에서 하이파 등을 직접 켭니다. 병행의 기본 주입은 누적 로그 전체이며 최근 K청크·기록만도 선택할 수 있습니다. 원문 관리에는 연대기의 최근 N턴 설정이 적용되지 않습니다.

완료된 AI 응답 1개가 1턴입니다. 첫 인사는 제외하며, 사용자 입력 없이 별도 메시지로 생성한 AI 응답도 셉니다. 요약 주기와 최근 원문 수는 별개입니다. 정상 요약이 권장 글자 수보다 길어져도 저장합니다.

## 웹·모바일 안전장치

설정창 맨 위의 **실행 환경 · 최근 기억 처리**에서 사용 가능 기능과 마지막 처리 결과를 확인합니다. Web Crypto를 사용할 수 없으면 기억 처리를 건너뛰고 RP 원문을 통과시키며 이유를 남깁니다. 원격 접속은 HTTPS와 최신 브라우저를 권장합니다. PC의 localhost는 일반 원격 HTTP 주소와 다르게 취급됩니다.

백업 버튼은 JSON을 먼저 준비합니다. 이어서 **JSON 파일 저장** 링크를 직접 누르고 브라우저·파일 앱에서 저장 결과를 확인하세요. 다운로드가 지원되지 않으면 **JSON 전체 선택**으로 복사할 수 있습니다.

요약 대기 중에도 설정창을 열 수 있습니다. **이번 기억 호출 기다리기 중단**을 누르면 저장한 청크와 미요약 원문으로 진행합니다. 늦은 응답은 기록·벡터에 반영하지 않으며 강제 대기 제한은 없습니다. 설정 저장·기록 수정·삭제는 진행 중인 작업 뒤에 처리하므로 필요하면 기다리기를 먼저 중단하세요.

이미 시작한 서버 호출·과금 취소는 보장하지 않습니다. 중단한 호출의 후속 API 호출은 생략하고 그 호출이 끝나기 전에는 같은 채팅의 새 기억 호출을 시작하지 않습니다. 호출이 끝난 뒤 기존 재시도 대기 또는 수동 요약으로 이어갑니다. 대기 상태가 끝나지 않으면 Risu 재시작으로 실행 중 대기 상태를 초기화할 수 있으나 서버 호출 취소를 뜻하지는 않습니다. 이미 저장한 청크는 유지합니다. 재시작 후 이전 처리 완료 여부가 불명확하면 안내를 표시하고, 다음 RP 요청이나 수동 요약 시 저장된 구간 뒤부터 확인합니다. 미저장 구간 재호출에는 비용이 다시 발생할 수 있습니다. 여러 기기·탭의 동시 실행을 조정하는 기능은 없습니다.

삭제 버튼은 대상과 **삭제 확인 / 취소**를 화면 안에 표시합니다. 확인창을 연 뒤 다른 채팅으로 이동해도 표시한 대상만 삭제합니다. 원문 전체의 변경 감지는 유지하며 동일한 본문의 해시를 재사용해 반복 계산을 줄였습니다.

API 요청은 Risu의 네트워크 설정을 따릅니다. 웹에서 프록시를 사용하면 요청 내용·인증정보가 해당 프록시를 경유할 수 있습니다. Risu 저장소의 디스크 반영이 지연될 수 있어 기록 완료 직후 앱을 강제 종료하면 최근 변경이 남지 않을 수 있습니다. 저장 방식은 Risu 버전·실행 환경마다 다를 수 있습니다.

**Risu 웹·PocketRisu·Android·iOS 실기 검증은 아직 하지 않았습니다.** 안전장치·자동 테스트·DOM 모의 검증을 추가한 것이며 화면 잠금 중 계속 실행되거나 실제 모바일 다운로드가 성공한다고 보장하지 않습니다.

## 연결과 보관

- 요약: Risu 내부 모델, OpenAI, Gemini AI Studio, Anthropic, Vertex AI, 직접 입력 OpenAI 호환 서버.
- 임베딩: OpenAI, Gemini AI Studio, Voyage AI, Vertex AI, 직접 입력 OpenAI 호환 서버. 자체 하이브리드에서 사용하며 단독·Risu 병행에는 필수가 아닙니다.
- 기록은 채팅별로 자동 보관하며 돌아오면 읽습니다. JSON 내보내기는 별도 백업용입니다.
- 조회·삭제: **Risu 설정 → Chronicle Memory → 저장된 기억 · 캐시 관리**. 기록을 삭제해도 원문·설정·API 키는 유지합니다.
- API 키는 기기에 저장하며 화면에서는 가립니다. 화면의 마스킹은 암호화 보관을 뜻하지 않습니다. 기억 백업에는 키를 넣지 않습니다.
- 선택한 제공자에 요약할 대화나 검색할 텍스트가 전송됩니다. 요약·임베딩·연결 시험에는 해당 제공자의 API 비용이 발생할 수 있습니다.

## 사용 전 알아둘 점

- 그룹 채팅의 기억 처리는 지원하지 않으며 해당 RP 요청은 통과시킵니다.
- 요약은 원문 일부를 생략할 수 있고 사실성 검증 기능은 아닙니다. 중요한 기록은 확인·편집·백업할 수 있습니다.
- 병행 모드의 연대기는 Risu 내장 기억 처리 뒤에 추가됩니다. 하이파가 누적 연대기 자체를 다시 줄여주지는 않으므로 최종 컨텍스트 여유를 확보하세요.
- 병행 모드는 Risu가 이미 제외한 원문을 복원하지 않습니다. 로그의 입력 토큰에는 설정된 최대 출력 토큰 예약도 영향을 줍니다.
- 플러그인 API 3.0을 기준으로 구현했습니다. 모든 Risu 버전·제공자·다른 플러그인 조합을 실기 검증한 것은 아닙니다. 구체적인 검증 범위는 [검증 문서](VALIDATION_v0.7.5.md)를 확인하세요.

## 개발·빌드

Node.js 22 이상을 사용합니다. 외부 npm 의존성이 없어 `npm install` 없이 실행할 수 있습니다.

```sh
npm run build
npm test
npm run release
```

`npm run build`는 플러그인 JS와 Control 모듈을 생성합니다. `npm test`도 필요한 빌드를 자동 수행하므로 깨끗한 소스에서 바로 실행할 수 있습니다. `npm run release`는 빌드 후 소스·테스트·라이선스를 함께 담은 ZIP과 SHA-256 파일을 `dist/`에 생성합니다. 실제 Risu와 API 연결 시험은 별도입니다. 생성된 설치 파일은 릴리스 ZIP에 포함됩니다.

오류 제보는 [Issues](https://github.com/HyunnJg/RisuAI_Chronicle_Memory/issues)에 Risu 버전, 모드, 요약 주기·최근 원문 수, 재현 순서, 가린 오류 메시지를 남겨주세요. API 키·서비스 계정 JSON·개인 대화가 포함된 전체 요청 로그는 올리지 마세요.
